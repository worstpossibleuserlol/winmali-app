# WinMali 2.0.0 Beta — 40-feature scope

This is the implementation scope for the 2.0.0 Beta cycle. Existing Winlator/WinMali foundations may be extended rather than duplicated. A feature is complete only after its implementation and relevant tests/build checks pass.

## Custom compatibility runtimes
1. Runtime library manager for user-imported Wine-compatible packages.
2. Support validated custom runtime archives, including supported tar.xz and tar.gz packages.
3. Runtime manifest with name, version, architecture, source, and detected capabilities.
4. Archive preflight validation before extracting files.
5. Clear rejection reasons for malformed or unsupported runtimes.
6. Per-container runtime selection with a visible selected-runtime label.
7. Safe runtime switching that preserves the container's existing prefix.
8. Runtime removal protection when a container still depends on that runtime.
9. Runtime integrity checks for required Wine binaries and libraries.
10. Runtime compatibility notes distinguishing Wine-compatible builds from full Steam Proton integration.

## Performance HUD and device telemetry
11. Live FPS counter with stable sampling and reset handling.
12. CPU utilization percentage from system CPU counters.
13. CPU clock-frequency reporting when exposed by the device.
14. RAM usage and total memory.
15. GPU utilization percentage only when a supported driver interface exposes a valid reading; otherwise show unavailable.
16. GPU renderer, vendor, and graphics API details.
17. Device thermal status when Android exposes it.
18. Battery level and charging state in the optional full HUD.
19. Frame-time sampling and basic frame-pacing information.
20. HUD mode and visibility controls that do not interfere with touch or pointer input.

## Container creation and lifecycle reliability
21. Create the rootfs home directory before allocating a container.
22. Show a useful error when container creation fails.
23. Check available storage before expensive prefix extraction.
24. Validate and normalize container names.
25. Prevent container ID and destination-directory collisions.
26. Build new containers in a staging directory before final placement.
27. Roll back partial extraction and clean temporary directories after failures.
28. Validate rootfs prerequisites before allowing creation.
29. Verify the selected Wine runtime and container pattern before extraction.
30. Refresh the container list only after a successful create, import, duplicate, or remove operation.

## Graphics, diagnostics, and supportability
31. Improve Mali GPU identification without treating Adreno-only Turnip as a Mali driver.
32. Keep Vulkan and OpenGL diagnostics separate and report unavailable APIs honestly.
33. Show backend compatibility warnings before selecting unsupported combinations.
34. Provide conservative graphics-driver defaults when hardware detection is incomplete.
35. Save and restore per-container graphics configuration safely.
36. Add per-session startup and process diagnostics.
37. Export diagnostic logs through Android's document picker.
38. Preserve useful failure details instead of swallowing every exception silently.
39. Add reusable environment-variable presets with validation.
40. Add a startup self-check for rootfs, Wine runtime, storage, and graphics prerequisites.

## Verification policy

- Do not label a feature complete merely because a UI control exists.
- Run unit tests and the Android debug build after changes.
- Fix build/test regressions before publishing.
- GPU utilization must never be fabricated; unsupported device interfaces must display “Unavailable”.
- A successful CI build does not replace testing on physical Mali hardware.
